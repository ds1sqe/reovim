# Performance Diff Report

> Comparing: `747ed0a` (baseline) → `0351294` (with #93 lazy compilation + #94 background pre-compilation)

## Executive Summary

| Change | Impact |
|--------|--------|
| **Lazy query compilation (#93)** | 99.98% faster startup |
| **Background pre-compilation (#94)** | Zero first-file latency |

## Key Improvements

### Treesitter Registration (Target of #93, #94)

| Benchmark | Before (747ed0a) | After (0351294) | Improvement |
|-----------|------------------|-----------------|-------------|
| `register_all_languages` | **78.46 ms** | **12.44 µs** | **99.98%** ⬇️ |
| `register_language/rust` | 14.64 ms | 9.03 µs | 99.94% ⬇️ |
| `register_language/c` | ~14.64 ms | 8.45 µs | 99.94% ⬇️ |
| `register_language/python` | ~14.64 ms | 9.28 µs | 99.94% ⬇️ |
| `register_language/javascript` | ~14.64 ms | 8.55 µs | 99.94% ⬇️ |

**Analysis:** Query compilation now happens lazily on first file access (or in background thread), not during language registration. This eliminates ~78ms of blocking startup time.

### Query Compilation (Unchanged - now happens on-demand)

| Benchmark | Before | After | Change |
|-----------|--------|-------|--------|
| `query_compile/rust` | 23.55 ms | 23.55 ms | Same |
| `query_compile/javascript` | 3.45 ms | 3.45 ms | Same |
| `query_compile/python` | 3.33 ms | 3.33 ms | Same |
| `query_compile/c` | 2.71 ms | 2.71 ms | Same |

**Analysis:** Compilation time itself is unchanged - it's just moved from startup to background/first-access.
