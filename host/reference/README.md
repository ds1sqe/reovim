# Reference Host

Portable driving uses Interface operation tables. With `std` on Linux,
`native::load(path)` maps a trusted artifact and admits the common module entry
through the SDK. Loading copies passive metadata; composition supplies grants
and activates the SDK module implementation through Runtime.

The loader selects no backend kind and constructs no Resource. SDK leases keep
the exact loaded executable and module data alive through dependent providers,
requests and destruction. Removing or replacing the artifact path does not
change an admitted instance.

The server native integration test starts Runtime before compiling its C module.
It loads through this public Host adapter, removes the artifact, discovers both
exports, binds their declarations and reads their distinct values. This does
not yet establish the running server/base Client process journey. Extended
fixtures cover registry activation, native dependency imports and exact-instance
unload. Server loading now queues declared artifact admission for Host driving;
boot and service now use this path. `process::Termination` owns Linux
SIGINT/SIGTERM notification; OS entropy supplies epochs and credentials. Actual
server process tests exercise startup, later admission and receipt-preserving
termination. The full base Client/backend journey remains open.

The old `export`, `snapshot`, worker and native contribution sources are
uncompiled donors. File snapshot/output behavior must migrate into Resource
modules with granted Host capabilities; the old Resource/Model constructors and
artifact factories are no longer public Host APIs. Their server consumers still
need migration. Source retention is not support or verification evidence.
