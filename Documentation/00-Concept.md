# Editing-System Concept

> **Normative contract index.** The linked chapters jointly define Reovim's
> required product direction and system model. Present-tense requirements do
> not assert that the current source tree implements them or that a release
> artifact is qualified.

Read the chapters in order:

1. [Product, system model, and Kernel](00-Concept/01-Product-System-and-Kernel.md)
   defines the North Star, obligations, system model, and portable Reovim
   Kernel boundary.
2. [State, semantics, Clients, and extensions](00-Concept/02-State-Semantics-Clients-and-Extensions.md)
   defines state authority, semantic/presentation ownership, neutral
   foundation, and extension direction.
3. [Quality, authority, and v0.16 proof](00-Concept/03-Quality-Authority-and-v016-Proof.md)
   defines mission-critical priority, evidence authority, release scope, and
   the foundation proof.

Each detailed clause appears in exactly one chapter. This index is navigation,
not a second requirement registry. The [Rule Matrix](06-Conformance/02-Rule-Matrix.md)
remains the stable obligation router.
