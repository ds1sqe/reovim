# Operation selection, binding and outcomes

Acquire [Resource access](01-resources.md), bind a declared interface, then
invoke its operation. Runtime validates declarations, grants, values and
readiness before provider execution. It retains the selected implementation
and drives admitted work independently of the caller's wait.

This chapter owns the common call path, independent of domain API packages.
[Domain interfaces](07-domain-apis.md) supply typed caller examples;
[Resource I/O](01.4-io.md) supplies transfer semantics. Native provider
records belong to [native dispatch](06.2-native-dispatch.md),
[state providers](06.3-state-providers.md) and [opened I/O](06.4-io-providers.md).

## Operation selection

Every operation below is available only when the subject offers the matching
interface and method and the opened access holds its required rights. Missing
support reports Unsupported; insufficient authority reports Denied. These checks
precede admission. Paired names group related operations, not a requirement to
support both directions. Common Kernel, server and Client code dispatch through
these generic interfaces without importing a domain API package.

| Operation | Selection and meaning |
| --- | --- |
| read/write | Data transfer through the opened stream I/O interface |
| read_at/write_at | Data transfer through the opened positional I/O interface |
| receive/send | Declared packets and local acceptance, preserving boundaries |
| exec | Invoke the already bound executable interface; no command number |
| ioctl | Invoke a nonzero command local to the bound control interface |

An ioctl number has meaning only under its retained binding. Typed wrappers
and dynamic callers use the same declared input/result schema; neither selects
a result schema per call. [Declarations](06-declarations.md) include a control
example; [modules](05.2-modules.md) own provider responsibilities.

write transfers data under its I/O contract and carries no command selector.
A Resource need not support data I/O. [I/O semantics](01.4-io.md) distinguish stream,
positional and packet operations. Kernel grants do not manufacture unsupported
provider capabilities. Partial transfers remain data outcomes, not partial
command invocation.

## Binding and values

[Interface declarations](06-declarations.md) own opaque ApiId keys,
method families, dispatch, canonical encoding, bounds and reference rules.
Typed and dynamic binding use those same checks. Reference capture follows
[Resource access](01-resources.md); admitted loans and result adoption follow
[request custody](01.3-requests.md).

The SDK captures borrowed input before handoff and owns decoded results.
A malformed provider result after possible effects retains recovery custody;
it cannot become a pre-admission rejection that authorizes replay.

## Outcomes

Request<T> awaits Result<T, RequestError>. Rejected proves no admission and no
requested effect. Failed reports a terminal failure with no outstanding effect
recovery; it does not promise that no effect occurred. Unknown carries a cause
and required recovery access to the original request.

Recovery represents caller-context request custody; its exact native/service
records belong to the [caller protocol](06.5-caller-protocol.md). Possessing a
request number or locator grants no access. Unknown remains explicit for an
ordinary awaited operation, not just an advanced polling API.

An Error preserves its machine cause and optional instance-qualified Resource
identity for diagnostics. That identity is metadata, grants no access and may
expire. It is independent of required recovery ownership. Unknown error codes
remain reportable and never authorize retry. Causes distinguish denied,
unsupported, invalid, unavailable, stale/conflict, pressure, cancelled, closed,
busy, incomplete shutdown and provider failure; effect classification is
separate.

Unknown retains unresolved effects through close/disconnect. Publication can
itself have partial/unknown target outcomes even when delivery succeeds.
A timeout or lost reply proves neither rejection nor failure.
[Retained requests](01.3-requests.md) define recovery without repeating work.
