# modprobe and module loading

`modprobe` requests a named [module](05.2-modules.md) and its required
dependencies. The name borrows the dependency-loading idea from
[Linux modprobe][modprobe]; Reovim's operation runs in Kernel Runtime. It
neither invokes the host's Linux command nor loads a Client extension.

Types: [ModuleScope and implementation](05.2-modules.md),
[Resource access](01.2-operations.md),
[request recovery](01.3-requests.md), [ResourceId](01-resources.md).

## Control API

Caller access selects one Kernel Runtime and authorized registry. A declaration
is passive metadata tied to an admitted implementation by composition or its
Host adapter. Registration validates that pairing; it executes no module code
and installs no package. Commands use their own Resource request contracts.

```rust
// Path: kernel/interface/src/module.rs; module: interface::module
pub struct ModuleInstance {
    pub resource: ResourceId, // Exact running-instance lifetime.
    pub declaration: ResourceId, // Retained immutable name/version/contracts.
    pub scope: ModuleScope, // Global or Session state scope in Kernel Runtime.
    pub lifecycle: Lifecycle, // Runtime state defined in chapter 05.
}
```

Optional module helpers use the common Resource path:

| Call | Result |
| --- | --- |
| register(declaration) | Registry-entry Resource; no code execution |
| modprobe(name, scope) | ModuleInstance after required contributions are Ready |
| describe(instance) | Passive metadata; no module callback |
| unload(instance) | Completion after cleanup, or busy before teardown |

All await ordinary results with RequestError. Borrowed names are captured
before queuing; returned instance IDs never follow replacement aliases.

An admitted package Resource offers `module::activation` for Global activation:
Exec requires EXEC, takes Unit and returns owned `Ref(module::control, READ|EXEC)`
after the captured graph is Ready. Resolve the package before invoking it;
inspection does not activate it. Reserve request/result capacity before module
construction. The returned access names the exact instance; it does not grant
access to the module's exports. Cancellation retains provisional rollback.

An instance Resource offers `module::control` through ordinary Interfaces/Bind:

| Command | Access | Input -> output |
| --- | --- | --- |
| status (ioctl 1) | READ | Unit -> U32 lifecycle |
| unload (ioctl 2) | EXEC | Unit -> Unit after cleanup |

Status codes are Constructed=0, Starting=1, Ready=2, Closing=3 and Closed=4.
Module or unfinished cleanup failure returns its Error, including diagnostic
identity; it does not prove cleanup ended. Unload remains pending during cleanup.
Cancellation before unload admission leaves the instance active; after admission
it is too late. Receipt recovery always observes the original request.

Register checks registry-write grants, declaration schema, compatible contracts
and implementation provenance. Existing identical registration is reused;
conflicting names reject. Code/metadata cannot replace a live instance by
changing its alias. Registry inspection uses ordinary Resource access.

```rust
// Proposed optional helper; modules uses granted caller access to this owner.
let instance =
    modules.modprobe("markdown-heading", ModuleScope::Global).await?;
// instance is Ready. Unknown retains recovery; retry cannot activate twice.
// Later describe/unload uses instance.resource, never a replacement by name.
```

## Resolve, load, activate

```text
registry:                              // Passive registration; no execution.
  text-state@1                        // Each alias pins one declaration.
  markdown-heading@1 -> text-state@1   // Required dependency.

modprobe("markdown-heading", Global):
  resolve authorized root + dependency declarations
  validate exact versions, contracts, scope, grants and graph bounds
  reject missing/ambiguous dependencies or cycles before activation
  retain selected declarations/implementations for this operation
  construct and drive text-state; wait for Ready
  construct markdown-heading with ModuleContext and granted imports
  drive activation outside Core authority; wait for Ready
  publish ready contributions; return its ModuleInstance
// This is execution order, not additional public function signatures.
```

Registry policy selects versions; search order is not a version policy.
Resolution captures exact declarations and dependency edges. Revalidate before
activation; an alias change cannot retarget pending work. Captured optional
absence also stays fixed when a dependency later becomes available. Each dependency
declares its required scope contract. A Session module may import a granted
Global provider; scope is never inferred from a registry path. Companion
Client modules use their own activation APIs. Their logical Kernel-service
dependencies can request authorized modprobe through
[composition](05.1-composition.md); Kernel modprobe never invokes a Client's
private loader. A contract API package alone needs no active module instance.

Reuse a compatible Ready instance within that owner/scope. Its retained
dependency instance identities must match the captured selection; different
edges conflict until the owner explicitly unloads/reselects. Session instances
have separate state even if they reuse the same loaded code. Global data is
shared only through an explicit grant. Concurrent requests
for the same selection join its activation; they do not run initialization
twice. Pending activations retain provisional dependency use. Committing one
activation keeps its shared instances; another request's rollback cannot remove
them. Different owners have separate instances/grants. An optional dependency
may be omitted only with a declared degraded behavior. Required failure never
publishes a half-active service or provider.

Loading makes an implementation callable; its [instance driver](05.2-modules.md)
performs activation and prepares authorized provider registrations. Runtime
checks every required contribution before publication; the instance's Ready
report alone is insufficient. The native direction is a versioned C ABI with
a Rust SDK; service adapters use their
versioned protocol. [Native modules](06.1-native-abi.md) owns loader and
binary requirements. Linked factories alone do not meet the requirement to
add providers without rebuilding or restarting Kernel.

## Failure, autoload and unload

Missing entries return unavailable; incompatible declarations/cycles return
invalid or unsupported; conflicting selections return ambiguous/conflict;
missing grants return denied. Diagnostics may name the dependency path.
Discovery/validation executes no module code. Retain required cleanup/recovery
even when optional diagnostics expire.

A dependency failure after Ready fences its consumers' contributions and
retains the failure on their instance identities. Cleanup drains consumers
before dependencies; Busy retains the dependency state needed by that cleanup.
A driver's Closed report does not retire surviving providers or destructors.
Keep driving while their cleanup waits. Independent instances continue running.

Failed activation rolls back only its provisional ownership, in reverse
dependency order. Preserve previously active or concurrently shared instances.
Unfinished cleanup stays owned and observable; failure/cancellation/timeout
cannot prove that code stopped. Keep result/cleanup access available while
closing. External effects and recovery survive disconnect/unload under the
[request contract](01.3-requests.md).

```text
authorized policy: Markdown context selected -> explicitly request modprobe
  // Autoload is an authorized policy trigger, not a lookup side effect.
  // Disabled/denied modules cannot load through another dependency path.
  // Missing support reports unavailable; observe/resolve never starts code.

unload(instance):
  check persistent dependants/data needing code; return busy before teardown
  fence new invocations; remove this Kernel module's contributions
  cancel/drain work, watches, borrows, results and cleanup
  release dependency use; retain code until its last use/cleanup has ended
  finish Closed; report request completion
// Repeated unload joins teardown or returns the retained Closed result.
// Unused dependencies follow explicit owner policy; shared dependencies stay.
// Companion Client extensions have independent owners and teardown APIs.
```

Busy preserves the active instance and its contributions. Active dependants,
open provider-backed Resources or Buffer/History values may require explicit
close/detach or migration first. After admission, outstanding calls/results
drain under Closing; cancellation or timeout cannot force code release.
Fence and recheck under the registration owner's authority so concurrent
access cannot escape the unload lifetime checks. No implicit forced cascade.

Runtime owns active instances; returned metadata adds no lease. Retained access,
pending work, dependency use and result destructors retain required code/data.
Closing one access does not unload the shared module. An expired instance
reference is unavailable and can never unload a replacement.

The [complete journey](07.2-module-journey.md) uses Session/global instances
and shows a state-provider unload returning busy while its Buffer remains alive.
