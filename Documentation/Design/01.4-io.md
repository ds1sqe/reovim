# Resource I/O

[Resource access](01-resources.md) owns handles; [operation selection](01.2-operations.md)
owns support and admission. This chapter owns transfer semantics.
[Native I/O](06.4-io-providers.md) owns callback records and encoded results.

## Stream, positional and packet transfer

Stream read/write transfer ordered bytes. Reads may consume incoming data;
short transfers are valid. A stream need not have a position or finite extent.
Positional read_at/write_at transfer bytes at explicit offsets; provider limits
specify alignment and extent. One interface does not imply support for another
or for both directions.

ReadResult is {transferred: usize, eof: bool}; zero bytes alone do not imply
EOF. A zero-maximum byte read is a no-op and establishes no EOF. Writes return
the accepted prefix count. Counts cannot exceed the admitted request. Sequential
cursor changes follow accepted transfer and are ordered per opened access.

Packet receive/send preserve one message boundary and declared metadata.
Empty packets remain items, not end-of-stream. Receive options select reject,
truncate or discard for oversized packets; reject must leave a packet unconsumed
or report Unsupported. Truncation/discard reports original length only if known.
A send receipt describes local acceptance, not delivery or peer processing.

Packet payload/addressing belongs to its provider's validated declaration.
Typed and dynamic callers use the same values; neither requires a global
packet enum. Sender/clock metadata exists only when supplied. ResourceInfo
exposes supported modes, limits and alignment before invocation.

## Progress and ownership

Opening a stream endpoint twice does not clone received data or manufacture
independent stream cursors. Its API must declare competing receivers, exclusive
receive access or explicit fan-out. Independent per-open file positions apply
only to subjects that actually have positions.

Native waits are cancellable and wake Runtime through Host adapters. Pending
read/receive must not stall unrelated writes, commands or cleanup. Define queued
work, fairness, byte bounds and close/cancel races; elapsed silence proves
neither EOF nor deadlock. Polling a user Future does not bypass execution
authority.

Receive consumes an external observation. If delivery to the caller is lost,
recovery returns the same captured bytes/message, not another socket receive.
Bound retained receive results and expose pressure. Send completion describes
the provider's known acceptance boundary, not successful processing by the peer.
Unknown effects remain unknown if no application-level reconciliation exists.

Positional data must declare short I/O, supported alignment and mutable extent.
Random access alone promises neither coherent snapshots nor durable writes.
Generic copy requires its own capture guarantee; live streams are not silently
converted into stable copyable storage.

## State and device use

[Buffer sources](02.2-sources.md) own capture/import and its stop boundary.
Buffer writes, when supported, use [editing](02-buffer.md) rather than a
separate live-state mutation. Immutable snapshot access is an additional
guarantee; ordinary I/O cannot manufacture it.

[Live examples](07.1-live-io.md) apply this contract to TCP, UDP, GPIO and
WebSocket. GPIO logical values, clipboard formats and settings use their own
declared APIs; they need not become byte-file formats. Reovim's service
transport and a Resource being inspected retain separate grants and owners.
