# Native modules and service adapters

New Resource, state factory, editing and semantic implementations must
load into an already running Kernel without rebuilding or restarting it.
The native boundary is a language-independent versioned C ABI. The Rust SDK
wraps it; a C module or host can implement the same contract directly.
The target records are defined by [native dispatch](06.2-native-dispatch.md),
[state providers](06.3-state-providers.md), [I/O/watch](06.4-io-providers.md) and the
[caller protocol](06.5-caller-protocol.md). The [Interface ABI][abi-types],
[C header][abi-header] and [Rust adapters][rust-sdk] are its implementation homes.
ABI stays SemVer 0.1.0 with reserved u32 zero.
[The overview](00-overview.md) describes compatible Clients, Kernels and hosts.

```text
Rust Kernel module -> Rust SDK -> native module ABI -> Kernel Runtime access
C Kernel module  -------------> native module ABI -> Kernel Runtime access
service module -> versioned protocol adapter -> Kernel Runtime access
// Both enter the public lifecycle/provider contracts under their own grants.
// Host adapters own library/process loading; portable Kernel stays no_std.
```

The Rust ABI has no stability guarantee; ordinary Rust generic tables and
trait objects cannot establish an independently built plugin contract.
[Rust ABI reference][rust-abi]. The native contract is specific to its admitted
platform/ABI version. Compatibility with arbitrary Kernel versions, platforms
or editor plugins is not implied.

## Required binary boundary

| Boundary | Required contract |
| --- | --- |
| Entry point | Versioned factory, descriptor layout/extent and exact supported ABI |
| Imports/exports | ApiId and complete declaration, table layout, instance and scope |
| Context | Opaque owned handle with explicit lifetime; no concrete Runtime/Core type |
| Values | Defined field layout, widths, extent and schema; no Rust-owned collections across ABI |
| Ownership | Borrow duration, transfer point, retain/release and allocator-specific destruction |
| Calls/results | Admission, pending work, cancellation, errors, uncertainty and cleanup |
| Execution | Thread/reentrancy rules, readiness/wakeups and no unwinding across ABI |

Keep Rust `Box`, `String`, `Vec`, Rust-specific reference lifetimes and
trait-object layouts behind the SDK adapter. A byte transport encoding does
not make every Resource byte-addressed.
[Canonical values](06-declarations.md) carry bounded data and
separately checked references under the bound operation's declaration. Adapters
translate reference ownership; no caller-selected result schema crosses this
boundary. Futures stay inside adapters.

Copy admitted metadata into owner storage or retain its code/data lifetime.
A string or destructor inside a library does not remain valid after unmap,
even if the Rust source declared it static. Data returned across the boundary
must name its matching release mechanism; the other side cannot guess which
allocator owns it.

[Native dispatch](06.2-native-dispatch.md) owns callback serialization, wake
retention, table validation and provider/result cleanup. [Module loading](05.3-modprobe.md)
owns inert construction, activation and provisional rollback.

## Module entry and execution

`rv_module_entry(void)` returns `const rv_module *` passive metadata. The record
contains its exact size, ABI Version, required relative export path array/count,
maximum exports and inert construct callback. Paths are Bytes(4096); both counts
are bounded by 256, and required_count cannot exceed export_limit. The adapter
copies paths and retains executable metadata under the artifact lease. Registry
selection/dependency metadata remains owned by [modprobe](05.3-modprobe.md).

Construction receives `rv_module_context`: exact size, instance Identity,
scope (Global=0 or Session=1), session Identity, namespace Identity, granted
`rv_caller` and activation-scoped `rv_registrar`. Global has zero session; all
other identities are valid Resources. The record is borrowed for construction;
copied caller/registrar tables stay valid through final instance destruction.
On OK it returns one owned `rv_module_instance` containing exact size, opaque
context, immutable driver pointer and required destroy callback. Rejection
leaves the output zero, with no effects or retained context. Malformed ownership
keeps cleanup/code rather than guessing that construction had no effect.

The driver has exact size and required status, advance and close callbacks.
status returns a passive phase: Constructed=0, Starting=1, Ready=2, Closing=3,
Closed=4, Failed=5. Only Failed carries a nonzero Error; all other error fields
are zero. advance borrows Wake and returns More=0, Idle=1 or Stopped=2. Stopped
requires Closed. close begins/joins teardown; Busy requires further driving.
Callback failures preserve Error detail under the common error rules.

Readiness never publishes directly. Runtime validates and installs the scoped
batch. destroy runs once after successful closing and the last provider,
request/result or other dependent owner; code and imported caller/registrar
contexts remain valid during destruction. Exported providers retain the native
instance data, not just the library mapping. A registrar owned by the instance
uses a weak link back and acquires a strong instance lease only when staging,
so this ownership graph has no permanent cycle.

## Load and release

Native loading itself is an execution boundary: platform library constructors
may run before entry-point validation; see [dlopen initialization][dlopen].
Passive registry inspection never loads a library. Failed load/activation
keeps any required cleanup owned; an error is not proof that no code ran or
that unloading is already safe.

[modprobe](05.3-modprobe.md) owns dependency reuse, provisional rollback and
unload admission. Removing registrations stops new users; code remains mapped
until calls, callbacks, instances, data leases and result destructors that
need it have finished. Persistent state can report busy. Replacement creates
a new instance; old access never dispatches to the replacement by alias.
Unloading one instance releases only its own use of the artifact. Other
instances or native-loader references may retain the mapping. Closed reports
the completed instance lifetime, not disappearance of every code page.

## Service and language adapters

Kernel service adapters can host language implementations outside the native
loader. Client extension adapters belong to their respective Client contracts.
Follow the [SDK/family matrix](../README.md): Python/TypeScript service surfaces
and process ownership remain separate from the native Kernel module ABI.
Native library loading is not the Web extension mechanism; no embedded
interpreter is selected. Building a TS GUI does not implement its extension SDK.
The [caller protocol](06.5-caller-protocol.md) defines exact operation bodies,
reference translation and result custody over retained service framing. It
rejects retired generic-Contract call fields at cutover. Independent native and
service witnesses must establish equivalence; no new negotiation is added.

Grants are not an in-process memory/crash sandbox. Native modules are trusted
code in their execution host. Service isolation/termination requires separate
evidence. No module callback or destructor runs under Core commit authority.
