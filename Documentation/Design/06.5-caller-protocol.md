# Caller, request and service protocol

This chapter owns caller-facing C records and service operation bodies.
[Requests](01.3-requests.md) own admission, adoption and recovery semantics;
[declarations](06-declarations.md) own values;
[native dispatch](06.2-native-dispatch.md) owns provider callbacks.

## Caller context and access

A Caller is authenticated and bound to one Kernel instance and Session. Explicit
bootstrap/system callers may have no [Session](04.1-session.md). Its
namespace/grants are explicit. Transport reconnect can resume that same Caller;
creating another Caller or switching Session does not retarget old handles.
Explicit Caller close fences its access and drains/adopts outstanding work.
Module imports receive a Caller under module grants, not a privileged Runtime.

```c
typedef struct {
    uint32_t present;
    rv_identity subject;
    uint64_t revision;
} rv_expected;
typedef struct {
    uint64_t request;
    uint32_t operation;
    rv_access subject;
    uint32_t command;
    rv_expected expected;
    rv_args input;
} rv_call;
typedef struct {
    size_t bytes;
    uint32_t (*reserve)(void *context, uint64_t *request);
    uint32_t (*submit)(void *context, const rv_call *call,
                       rv_pending *output, rv_error *error);
    uint32_t (*result)(void *context, uint64_t request,
                       rv_pending *output, rv_error *error);
    uint32_t (*cancel)(void *context, uint64_t request);
    uint32_t (*reconcile)(void *context, uint64_t request);
    uint32_t (*adopt)(void *context, uint64_t request);
    uint32_t (*release)(void *context, uint64_t request);
} rv_caller_ops;
typedef struct { void *context; const rv_caller_ops *ops; } rv_caller;
```

The caller table has the same size/null checks as provider tables. reserve
allocates a nonzero monotonic ID and bounded request record before effects.
submit captures/canonicalizes the exact call into that record and admits once.
Repeating identical submit joins it; differing content with the same ID rejects
Conflict. Reference identity includes the access token, not only subject ID.
Unused fields must be zero. Invalid/pre-admission calls return an error without
provider execution; the reservation remains explicitly releasable.

Caller pending views expose the Runtime-owned outcome, not direct provider take.
Closing a view releases that delivery view; the request remains under result
custody until adoption/release. This is distinct from finishing the provider's
execution context. SDK Request<T> hides reserve/submit/pending choreography.

Native result returns NotReady with untouched pending output for a Reserved
receipt; Pending or Outcome produces a delivery view. Creating a view reserves
its bounded storage before submission. View finish releases only that view and
returns Busy while one of its taken outcome owners is outstanding. Original
request recovery/adoption/release still uses the Caller table. Snapshot-style
service/native result lookup registers no waker; pending view poll can register
wake interest. Thus repeated recovery queries do not consume waiter capacity.
Caller-view poll accepts an all-zero Wake for passive readiness inspection.
Nonempty Wake records require all callbacks; repeated use of the same wake
owner preserves one registration. This optional signal is specific to caller
delivery views; Runtime supplies a retained wake when polling provider work.

## Common operation bodies

All below are common mechanisms, not a list of module-specific commands.
Declared input/output refers to a bound module API only for exec/ioctl.

| Code | Operation | Input | Result value |
| --- | --- | --- | --- |
| 1 | Acquire | locator | identity, zero held rights, owned access |
| 2 | Interfaces | page cursor, byte limit | declaration page, next cursor |
| 3 | Bind | offered/expected declaration | owned qualified access |
| 4 | Info | Unit | identity, rights, flags, times, optional I/O description |
| 5 | Entries | page cursor, byte limit | name/identity page, next cursor |
| 6 | Read | maximum bytes | bytes, EOF indicator |
| 7 | Write | bytes | transferred count |
| 8 | ReadAt | offset, maximum bytes | bytes, EOF indicator |
| 9 | WriteAt | offset, bytes | transferred count |
| 10 | Exec | declared input | result according to declared dispatch |
| 11 | Ioctl | declared input | result according to declared dispatch |
| 12 | Close | Unit | Unit after access cleanup |
| 13 | Create | name | Acquire result, through the parent's default factory |
| 14 | Delete | child name | Unit |
| 15 | Copy | source access, destination name | created access |
| 16 | Link | source access, destination name | Unit |
| 17 | Rename | Record(old:Bytes(4096), parent:Ref(AnyResource,WRITE), new:Bytes(4096)) | Unit |
| 18 | Receive | receive options | item/end and metadata |
| 19 | Send | declared packet | acceptance receipt |
| 20 | Capture | narrowed rights | independently owned access to opened state |
| 21 | SetAccess | access flags:u32 | Unit after held flags change |

Acquire uses subject=0; locator is Choice(Path Bytes, Identity). Initial
operation rights are zero. SetAccess changes the existing handle under caller
grants; typed resolve composes Acquire, SetAccess and Bind. Other calls use
existing access. Exec has command=0; ioctl uses its local command. Naming
mutations act on a parent/container access, with separate destination/source
references as listed. Only an Edit-dispatched call requires expected for
mutation; READ-only queries may omit it and capture the current state. Buffer
byte writes capture currentness at admission if not explicitly supplied, then
reject stale commit.

Bind returns a qualification of existing access under the
[Resource lifetime rules](01-resources.md); Capture returns an independent
close fence over that same opened implementation. Neither calls open again.

Record field order is the order shown. Page cursor/limits/counts/offsets are
u64; namespace names are Bytes; owned access is Ref; identity is Identity.
Fixed Core result records use the canonical type grammar, as do node times and
I/O/watch records in their owner documents. No result introduces a freely chosen
output schema. Factory result is {created: Ref, value: declared output}; edit result is
{state: BufferState, value: declared output}. BufferState is identity +
revision. Core result prefixes are reserved before installation; no domain
payload is interpreted or serialized by callbacks under the commit cut.

Generated SDK methods select these codes and validate their result records.
Watch ioctls follow [observation](03-observation.md).

Link input is Record(source: Ref(AnyResource, 0), name: Bytes(4096)): slot zero
and exactly one source reference; the result is Unit.

### Acquisition and binding codecs

Acquire's locator is Choice with tag 0 `path: Bytes(4096)` and tag 1
`identity: Identity`. Its result is Record(identity: Identity, access: U32,
handle: Ref(AnyResource, 0)); access is initially zero. Paths are absolute in
the caller's namespace. Ref uses slot zero in a one-element reference vector.
Bind input is Bytes(65536) containing the complete canonical declaration; its
result is Ref(the bound API, 0), sharing the existing opened access and fence.
SetAccess input is U32 with known READ/WRITE/EXEC flags; result is Unit.
Capture input is U32 access flags; result is Ref(AnyResource, 0).
Close input and result are Unit. These inputs contain no reference slots.
Transport and caller limits may reject smaller bounds with Pressure before
admission. Unknown locator tags and trailing bytes reject Invalid.

Interfaces input is Record(cursor: U64, byte_limit: U64). Cursor zero starts
the ordered declaration list retained by the opened Resource. Result is
Record(declarations: Sequence(256, Bytes(65536)), next: U64). Sequence and Bytes
length prefixes are canonical U32; next is zero at the end, otherwise the index
of the next declaration. A cursor past the list rejects Invalid. The byte limit
bounds the complete result, including its prefixes and next cursor, and is
capped by caller limits. A nonterminal page contains at least one complete
declaration; insufficient bytes or value elements reject Pressure. No declaration
is split. Empty lists return an empty terminal page. Discovery requires live
access but no held operation rights; retries recover the original page.

Info input is Unit. Its result is Record(identity: Identity, access: U32,
flags: U32, times: Times, io: Option<Io>,
interfaces: Sequence(256, Bytes(65536))).
Times is Record(atime, mtime, ctime), each Option<Timestamp>. Timestamp is
Record(seconds: I64, nanoseconds: U32). Option uses Choice(None=0 Unit,
Some=1 value). Io is Record(read_modes: U32, write_modes: U32, alignment: U64,
transfer_limit: U64, receive_type: Bytes(65536), send_type: Bytes(65536)).
Absent packet support uses empty Type bytes, not a Unit packet declaration.
[Metadata](01.5-metadata.md) owns flags/times; [I/O](06.4-io-providers.md) owns
support and limits. Unknown Host time is None. Info is passive and requires
live access but no held operation rights. Its copied rights reflect that opened
handle. Retry returns the original observation, even after rights change.
The complete result must fit caller byte/element bounds or reject Pressure;
Interfaces paging remains available for bounded declaration discovery.

The operation table is not yet a complete codec specification. Composite
I/O choices and publication progress
still need exact bounded Type records and tags at their owners. Field-order and
primitive conventions alone cannot establish independent codec compatibility.
[Declarations](06-declarations.md) owns progress and created-Ref qualification.

## Service envelope

The existing authenticated opening/boot flow creates or resumes a Caller.
The following fields are carried by its bounded length-framed transport:

```text
reserve(caller) -> request
call(caller, request, operation, subject, command, expected, data, refs)
result(caller, request) -> Reserved | Pending | Outcome
cancel(caller, request)
reconcile(caller, request)
adopt(caller, request)
release(caller, request)
```

These are structured fields, not shell strings. The reference text codec uses
decimal strings for integers/tokens, hex for canonical bytes/identity epochs,
and ordered reference arrays. expected is absent or {identity, revision}; it
is never inferred from data length. JS bindings retain u64 using bigint/string,
not Number. No native pointer or context address crosses the transport.

The service framing/opening profile carries these operation bodies; it accepts
no generic-Contract call fields or caller-selected result schema. Batching may
reduce exchanges while preserving reservation and deduplication. Request
recovery remains limited to its declared Runtime lifetime; persisted restart
intent requires a separate durable owner.

### Reference text frames

The local profile uses UTF-8 tab-separated fields terminated by one newline,
with at most 65536 bytes including that newline. An authenticated opening owner
maps a lowercase 32-hex-digit caller token to the retained Caller. The token is
a credential, not a Resource identity. The operation endpoint checks that token
before dispatch; opening and transport authentication remain host-owned.
Credential routing retains the same Caller across socket loss and has no second
receipt table. Retirement keeps result/recovery access until binding cleanup
finishes, without affecting other Callers. A retired credential cannot select a
replacement Caller; credential retention has its own finite Host budget.

Frames begin `v1`, caller token, action. `reserve` appends a nonzero client
sequence, distinct from the allocated request ID. One coordinator per Caller
persists this increasing sequence before transmission and retries it until the
allocation reply arrives; only then may it issue a higher sequence. Other request
operations need not wait. Keep the same endpoint across sockets: it retains only
the latest successful sequence/ID acknowledgement, including after ID release.
An equal sequence returns that ID without allocating; older sequences reject
Closed. Failed allocation leaves the previous acknowledgement intact. Sequences
never wrap; advancing successfully acknowledges the prior allocation. Native
Caller reserve stays unchanged; this sequence belongs to service delivery.

`result`, `cancel`, `reconcile`, `adopt`, `release` append one request number.
`call` appends request, operation code, subject token, command, expected epoch,
expected serial, expected revision, data hex, reference tokens. Absent expected
is `-`, `0`, `0`; present expected uses its 32-digit epoch and nonzero serial.
Numbers are unsigned canonical decimal without leading zeroes. Empty bytes or
references use `-`; reference tokens are comma-separated decimal in slot order.

Replies are `reserved` plus the allocated/recovered ID; `accepted` for a submitted
call or successful control; `cancelled` plus 0 (Accepted) or 1 (TooLate); or
`reserved`/`pending` for result status. `ok` appends data hex and references.
`failed` appends error code, detail epoch, detail serial. `unknown` appends those
same error fields, progress-present (0/1), progress data hex. Absent error detail
uses `-`, `0`; absent progress uses `0`, `-`. Progress has no references.
`error` plus error fields reports a rejected call/control, never an admitted
effect outcome. A lost reply is missing evidence, not an `error` frame.
Retired command-name/Contract/version call shapes reject before dispatch.

## Custody records

The [request state machine](01.3-requests.md) applies equally to native and
service callers. Delivery views do not take provider ownership. UNKNOWN output
cannot be adopted as success; releasing a view never discards pending cleanup.

Released IDs are never reused. Since every ID was reserved, an absent ID below
the allocation frontier is Retired, not an unsubmitted new call. Delayed retries
cannot resurrect it. Unused reservations occupy bounded custody until released.
