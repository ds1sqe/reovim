# Opened I/O, namespace providers and watches

This chapter owns generic native I/O/namespace callbacks and watch delivery.
[Resource I/O](01.4-io.md) owns transfer and device/protocol semantics;
[domain APIs](07-domain-apis.md) own extension values and their meaning.
Common pending and argument/result records come from
[native dispatch](06.2-native-dispatch.md); creation records come from
[state providers](06.3-state-providers.md). Domain APIs use these records without
adding domain-specific callbacks or packet/event enums to the common host.

## Subject versus opened implementation

A published subject can supply an open callback. It stages an implementation
for one opened access, preserving the subject's ResourceId. That implementation
owns its cursor/access-specific state; it is not another Resource. Without a
callback, access uses the subject's tables and Kernel-owned access bookkeeping.
Binding another API view does not open again. A fresh Acquire does.

```c
typedef struct {
    void *context;
    uint32_t (*stage)(void *context, const rv_provider *implementation);
} rv_open;
typedef struct rv_open_ops {
    size_t bytes;
    uint32_t (*begin)(void *context, const rv_open *opened,
                      rv_pending *output, rv_error *error);
} rv_open_ops;
typedef struct {
    uint32_t positional; /* 0 sequential, 1 explicit byte offset. */
    uint64_t offset;     /* Zero for sequential requests. */
    uint64_t maximum;
} rv_read;
typedef struct rv_write {
    uint32_t positional;
    uint64_t offset;
    rv_bytes data;
} rv_write;
typedef struct rv_io_ops {
    size_t bytes;
    uint32_t read_modes;  /* sequential=1, positional=2; zero if unavailable. */
    uint32_t write_modes; /* Same bits, independent of read support. */
    uint64_t alignment;      /* Byte offset/transfer alignment; at least 1. */
    uint64_t transfer_limit; /* Nonzero per-call byte limit. */
    rv_bytes receive_type; /* Canonical Type for one received packet. */
    rv_bytes send_type;
    uint32_t (*read)(void *, const rv_read *, rv_pending *, rv_error *);
    uint32_t (*write)(void *, const rv_write *, rv_pending *, rv_error *);
    uint32_t (*receive)(void *, const rv_args *, rv_pending *, rv_error *);
    uint32_t (*send)(void *, const rv_args *, rv_pending *, rv_error *);
} rv_io_ops;
```

The open staging callback validates/retains its implementation before exposing
access. OK without staging rejects; failure cleans the staged owner. It can
wait using ordinary pending custody. Open returns Unit without references or
operation activity; UNKNOWN carries no progress payload. Closing fences that
access; the opened implementation drains after its last access/request owner,
as specified by [Resource lifetime](01-resources.md). Captures retain the shared implementation.
Tables belong to the provider/code lease, never borrowed caller stack memory.
Acquisition starts with no operation rights. Runtime applies SetAccess against
caller grants and offered support without invoking open again.

Read returns Record{data:Bytes, eof:Bool}; write returns U64 accepted bytes.
Byte I/O UNKNOWN progress, when present, is U64 known transferred bytes.
Counts cannot regress across recovery; a known partial transfer returns a short
successful result once uncertainty settles.
[I/O semantics](01.4-io.md) own transfer counts, EOF, cursor order and the
provider's competing/exclusive receive policy.

ReceiveOptions is {maximum:u64, oversize:Reject|Truncate|Discard}. Truncate
returns an Item with truncated=true; Discard reports Dropped. Receive result:
Choice(Item {value:Packet, truncated:Bool, original:Option<U64>},
Dropped {original:Option<U64>}, End). Send returns {accepted_bytes:u64}.
Extra protocol metadata lives in Packet's Type. Packet UNKNOWN carries no
progress payload; reconciliation returns the original final result. Maximum and
original length measure provider-defined packet data; declared metadata and the
result envelope also obey the caller's canonical value bounds.

Provider receive_type/send_type are validated finite Type descriptors. Thus UDP
addressing or WebSocket frame metadata is not a Kernel-wide packet enum. Bodies
use canonical values and checked references; malformed or oversized requests
reject before I/O. Source loss and uncertain sends retain their declared
outcome/recovery semantics. Host/native alignment requirements do not permit
borrowing an invalid or misaligned caller buffer for DMA. read/write callbacks
are nonnull exactly when their direction's mode mask is nonzero; unknown bits
reject. receive/send callbacks independently advertise packet support. Packet
Type descriptors are empty exactly when that callback is absent. Admission
checks the selected direction and mode before invocation. Opened implementations
cannot add APIs/rights absent from the subject's offers. Info exposes
read_modes, write_modes, alignment, transfer_limit and packet Type descriptors,
so dynamic callers can validate packets before submission. Extent is observed
through the provider's declared size/control API, not a promise that positional
access is immutable. Limits/alignment are checked before invoking I/O.

## Namespace provider identity

A mounted namespace provider maps names to opaque object keys stable within that
provider instance and object lifetime. Kernel interns live (instance,key) pairs
to ResourceIds; multiple names for the same live key select one subject.
Replaced objects must use a new key/generation. Reclaimed Kernel identities
never retarget; a later materialization is a new lifetime. Buffer
attachments/handles retain the identities they require. Key equality does not
grant caller rights.

```c
typedef struct rv_namespace_ops {
    size_t bytes;
    uint32_t (*flags)(void *, rv_pending *, rv_error *);
    uint32_t (*lookup)(void *, rv_bytes name, rv_pending *, rv_error *);
    uint32_t (*list)(void *, uint64_t cursor, uint64_t byte_limit,
                     rv_pending *, rv_error *);
    uint32_t (*materialize)(void *, rv_bytes key, const rv_creation *,
                            rv_pending *, rv_error *);
    uint32_t (*create)(void *, rv_bytes name, const rv_creation *,
                       rv_pending *, rv_error *);
    uint32_t (*remove)(void *, rv_bytes name, rv_bytes expected_key,
                       rv_pending *, rv_error *);
    uint32_t (*link)(void *, rv_bytes name, rv_bytes source_key,
                     rv_pending *, rv_error *);
    uint32_t (*rename)(void *, const rv_args *, rv_pending *, rv_error *);
} rv_namespace_ops;
```

flags is required when this table is offered. It returns canonical U32
CONTAINER (1) or CONTAINER|EMPTY (3), without reference slots or activity.
It observes visible children without making Info perform enumeration. Failure
and uncertainty use ordinary request custody; neither means an empty container.
[Metadata](01.5-metadata.md) owns the flag meanings and passive observation rule.

lookup reports zero activity and returns canonical Bytes containing the opaque
key. list returns
Record{entries:List<Record{name:Bytes,key:Bytes}>,next:U64}; next zero ends the
enumeration. These values contain no reference slots. materialize returns Unit
after staging one primary subject provider for an unresolved key,
revalidating the key's identity. Concurrent materialization joins one interned
identity; losing staged providers are cleaned outside guards. This mechanism
supplies lazy filesystem hierarchies; ordinary Kernel-published directories use
the built-in entry implementation of the same namespace responsibilities.

create invokes the default child factory with no initializer payload. It uses
[keyed primary staging](06.3-state-providers.md) before publishing an exclusive
name, returning Unit without references and at most parent WRITE activity.
remove revalidates the name's captured
key, rejects nonempty containers, and returns Unit without reference slots.
Its allowed activity is WRITE on the parent; lookup remains passive. Recovery
continues the original mutation rather than looking up the name again.
rename receives Record(old name Bytes, captured key Bytes, destination
Choice(Root Unit=0, Key Bytes=1), new name Bytes), without reference slots.
Runtime verifies WRITE on both opened parents in one mounted namespace and
retains them through cleanup; the provider receives its own destination key,
not a caller handle. Root explicitly selects the mount; empty keys remain valid.
The provider atomically revalidates the source key and destination absence,
returns Unit and reports at most WRITE activity on both parents. Recovery
continues that original no-replace mutation. For link, Runtime verifies the
opened source and destination share
one mounted namespace, retains source access, and passes its interned source
key. The provider revalidates that key and destination absence, returning Unit
with at most parent WRITE activity. No Kernel identity map belongs in the
provider. Unsupported foreign links/moves reject rather than copy. Names follow
the [namespace rules](01.1-namespace.md); ambiguous mutations reject.
Caller rights and explicit ownership scopes are enforced by Runtime separately
from provider filesystem permissions. Namespace ancestry never changes grants.

## Watch encoding

[Observation](03-observation.md) owns watch acquisition, delivery, baseline and
loss semantics. Providers use Factory-dispatched ioctl for acquisition and
Call-dispatched ioctl for NEXT through the ordinary creation/control tables.

NEXT input is {wait:Bool, maximum:u32}; maximum is nonzero. Its result encodes
Next<E> using Choice tags Items=0, Pending=1, Gap=2, End=3. Item sequence
numbers are per subscription. E comes from the selected observation API
declaration; the generic host contains no source-specific event enum.

## Provider wiring

rv_provider carries optional open, io and namespace table pointers in addition
to custom interfaces. Snapshot providers expose readonly operations. Mutable
Buffer data writes route through its staged editing binding, not io.write on
live private state. Modules register observation control/factory interfaces like
other APIs. This supplies filesystem, device and state events without a global
enum of provider-specific methods or source-specific event payloads.
