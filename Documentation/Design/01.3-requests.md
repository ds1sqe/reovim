# Interrupted requests and retained work

Ordinary calls await results. A save or GPIO pulse can execute before its reply
is lost. Recovery must observe that original work without submitting its effect
again. Runtime owns request identity, input and result custody independently
of delivery views or caller futures.

```text
reserve -> submit once -> Pending -> Outcome -> Adopted -> Released
                           |           |
                    lost delivery   UNKNOWN -> reconcile original work
// Repeated identical submit joins the original request.
// Changed input with the same identity rejects Conflict.
```

The [caller protocol](06.5-caller-protocol.md) owns native records, common call
bodies, service framing and adoption states.
[Native dispatch](06.2-native-dispatch.md) owns provider
begin/poll/take/cancel/reconcile/finish. SDK Request<T> wraps these mechanisms
and returns the operation's declared result.

## Reserve before effects

Before transmission, reserve a nonzero monotonic ID and bounded request custody
in the authenticated Caller. A transported reservation must recover its original
allocation acknowledgement before submitting effects; the service protocol owns
its idempotent sequence. Admission captures the operation, bound access,
local ioctl command when applicable, expected state, canonical bytes and actual
reference identities. Retrying identical submission joins that work/result.
Changing any captured field rejects; resolving a new alias does not establish
identity. References include the access token, not merely their subject ID.

Reconnect resumes the original Caller under authorization. Session switching
cannot retarget its handles or requests. Recovery can return Reserved, Pending
or the retained Outcome. Reserved proves no call was admitted for that record;
the original frame may be submitted. Missing evidence is not that proof.
Retired IDs cannot be reused or resurrected by delayed retries.

A caller-local request number identifies custody. Its causal InteractionId is
the Kernel epoch plus an internal monotonic request serial; events may copy it
without granting recovery access. It is distinct from ResourceId.
No native pointer crosses a service transport.
The contract retains work within one Runtime lifetime; process restart needs
separately specified durable intent and cannot infer non-admission from loss.

## Results and adoption

Runtime validates provider outcomes under the bound result declaration and
retains their values/references. Provider take transfers an owner once per
outcome generation. Multiple delivery/recovery readers view the same retained
result; they do not each take provider ownership or allocate another watch.

SDK validates and constructs returned handles before adoption. Adoption is
idempotent for the original request and transfers its returned access once.
Releasing a receipt then leaves those handles alive under their new owners.
Releasing an unadopted result cleans its output access under Runtime custody;
it does not destroy independently published or shared subjects.

UNKNOWN may carry declared progress but no returned access. Reconciliation can
refine evidence on the same provider context without calling exec/ioctl again.
Earlier observed outcomes stay immutable. Final OK/FAILED cannot be reopened.
Absent reconciliation support leaves uncertainty explicit; it never licenses
automatic retry. Diagnostics and observation events cannot settle an effect.

## Cancellation and close

Cancellation is a request, not rollback. Accepted cancellation does not prove
an external effect did not occur; the final outcome supplies that evidence.
Dropping the waiting future or pending delivery view cannot abandon admitted
execution or its cleanup. Handle Drop requests nonblocking close; explicit
close fences new operations and joins retained cleanup.

Request recovery belongs to the Caller and remains available after subject
handle close. Runtime retains the provider, arguments, selected state and code
needed by admitted work. Replacing the provider cannot redirect it. Unload
waits for callbacks, results and destruction to drain.

Provider finish returns OK only after pending execution, output and cleanup
obligations have ended; BUSY leaves the owner retained and progressable.
Caller close similarly drains or transfers outstanding custody and reports
incomplete shutdown when it cannot finish. Timeout is neither settlement nor
permission to free executable code.

## Bounds and evidence

Reserve cleanup/completion capacity before returning access or admitting work.
Pressure rejects new admission instead of dropping an existing obligation.
Unresolved effects cannot expire into apparent rejection. Where settled result
retention expires, retrieval reports unavailable evidence without authorizing
another effect. Runtime drives completion outside Core's commit authority;
polling readiness is observation, not execution by the caller.
