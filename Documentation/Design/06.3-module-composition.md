# 06.3 — Module composition through semantic Resources

A module requires public contracts; composition selects their providers and
supplies [granted access](05.1-composition.md). This applies between Kernel
modules, between Client modules, and from a Client module to Kernel services.
Each execution owner keeps its own activation and teardown contract.

## Structure, navigation and commands

```text
treesitter -> lang-tree/api             // Implements language structure.
lang-tree -> lang-tree/api + navigation/api
vim, emacs -> navigation/api + public editing APIs
vim-motion-helper -> navigation/read + vim/api + Client surface/timer APIs
// Source dependencies: API packages contain no live provider instance.
// Vim/Emacs import neither lang-tree nor treesitter.
```

`lang-tree/api` defines structural items such as function and block. The
`treesitter` provider maps language-specific syntax into that contract.
The `lang-tree` module consumes a selected structure provider and exposes
generic navigation Resources. It maps item extents into the consumer's
supported Representation; missing correspondence rejects. Importing the API
creates no activation cycle or requirement to expose parser-node handles.
The [Tree-sitter reference](08-references.md) explains the parser boundary.

```text
buffers/draft/navigation/function  // Selector service, supplied by lang-tree.
buffers/draft/navigation/block     // Another target with the same public API.
// Illustrative aliases; each target is a Resource with granted typed access.
// Parser nodes need no individual Resource identity or Kernel enum variant.
```

The shared navigation API lives outside the parser and language-tree APIs.
It reuses [Position, Selection and Observed](03.1-representation.md). `at`
below is a qualified Position in the negotiated RepresentationSchema.
Discovery, movement and selection have distinct query contracts and grants;
the same [Resource request path](01.2-resource-access.md) carries each one.

```rust
// Proposed navigation SDK; target is a granted selector Resource.
let items = navigation.observe_items(&at).await?;
// Snapshot + watch; snapshot carries observed and resource/label items.
let position = navigation.locate(target, &at, movement).await?;
let selection = navigation.select(target, &at, object).await?;
// Items describe applicable targets at observed; they grant no invocation.
// movement/object requests use the profile's relations/forms and counts.
// Results are qualified Position/Selection values; selection may be disjoint.
```

Compatible schemas and grants are required. The provider defines supported
relations, Inside/Around boundaries and count behavior under its public
profile; Vim does not infer them from parser nodes. Unsupported or ambiguous
queries report that result. A parse for an older Buffer state cannot supply
a current selection. Pending interpretation waits or reports not-ready;
replacement, invalidation and [gaps](03-observation.md) require renewed access
or observation. Events invalidate/refresh data; queries return results.

## Delete around a function

Client configuration binds text-object key `f` to the function selector
Resource. The Kernel provider supplies semantic targets; Client policy owns
their key associations. The navigation API builds the Around/count request.

```rust
// Proposed SDK; inputs: scoped text_objects, qualified at, count and editor.
// Vim's resolver has recognized d + a + f; the operator is delete.
let target = text_objects.resolve("f")?; // Selected Resource, no provider name.
let object = navigation_api::around(count); // Public selection request.
let selected = navigation.select(target, &at, object).await?;
let changed = editor.delete(selected).await?; // Normal qualified semantic edit.
// Emacs can bind its own command to the same selector and editing contracts.
```

Selection is a read result; only the explicit delete changes Buffer/History.
[Core](03.2-editing.md) revalidates and installs that edit atomically. It owns
no function/block types, key sequences, navigation policy or help display.
Changing the parser implementation needs no change to Vim/Emacs imports.

## Read-only motion help

`vim-motion-helper` is a Client module. Its imports are deliberately narrow:

| Import | Access |
| --- | --- |
| Navigation items | Read/observe applicable semantic targets and descriptions |
| Vim command context | Read/observe pending input and valid resolver continuations |
| Client timer | Wait for the configured help delay; cancel on changed input |
| Client surface | Present/dismiss this helper's overlay in the initiating input scope |

Vim's public context identifies the Client/input scope, pending-command
generation and qualified position. Its continuation query uses the actual
resolver/keymap and current target availability. The helper implements no
second resolver and knows no lang-tree or treesitter schema.

```rust
// Proposed Client SDK; inputs: granted APIs above and configured help_delay.
// input_scope is this Client's active resolver/surface scope.
let pending = vim.observe_pending(input_scope).await?; // d awaits a motion.
timer.idle(help_delay, &pending).await?; // Cancel on changed command/context.
let items = navigation.observe_items(&pending.position).await?;
let hints = vim.read_continuations(&pending, &items).await?;
surface.show(&hints, &pending, &items.snapshot.observed)?;
// Presentation checks Client context/current observations before installation.
// Possible hints: w = next word; af = around function; if = inside function.
// Show only supported configured continuations, not every advertised target.
```

The helper has read/query access to semantic/module state and writes its own
Client surface. A query request write grants no content mutation. It receives
no edit, publication, module-control or shared-state-write authority.
Showing help never activates a provider or executes the pending command.
Unavailable targets remain unavailable; observation owns only its access and
subscription bookkeeping.

New input, focus/Buffer changes, provider invalidation, gaps or disconnect
cancel stale work and dismiss stale hints. Release observations/watches/timers
on replacement or close. Help visibility is local even when Clients share a
Session; removing the helper leaves Vim's command behavior intact. Selecting
a command later revalidates its actual target and editing preconditions.

The concrete structure/item/request schemas, observation lifetime and Client
pending-command/continuation tables remain to be specified in their public API
profiles. These sketches do not claim running implementations.
