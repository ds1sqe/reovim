# Buffer sources, attachments and capture

An attachment associates a Buffer with external input under provider-defined
roles. It records granted source access and a generation; historical provenance
belongs to selected state and supplies no live access or save permission.
[Buffer](02-buffer.md) owns state and graphs; [publication](02.3-publication.md)
owns destinations and effects. [State providers](06.3-state-providers.md) own
native staging and backing callbacks.

The one-source conveniences select the provider's single default backing role:

```rust
buffer.attach(&source).await?;
buffer.refresh(policy).await?;
buffer.save().await?;
let changes = buffer.watch(WatchTarget::Backing).await?;
buffer.detach().await?;
```

They reject missing/ambiguous roles. They never pick an arbitrary input or save
all predecessors. attach changes no content or saved evidence; detach preserves
Buffer state/History and does not close shared sources or unrelated attachments.
A replacement association has its own generation and cleanup owner.

## Attachment records

```rust
struct SourceEntry {
    key: String,              // Provider-defined role/member key; unique.
    source: ResourceHandle,    // Captured READ access.
    base: Option<Snapshot>,   // Exact selected state/base when available.
    publish_to: Option<ResourceId>, // Metadata, grants no WRITE access.
}
```

Attachments are Vec<SourceEntry>, encoded as a Sequence of records: key Utf8,
source Ref(AnyResource,READ), optional base Ref(AnyResource,READ), optional
publish_to Identity. Its bound is the Buffer/source-count limit advertised by
Runtime; standard optional fields use Choice(None=0 Unit, Some=1 value). This is
also rv_buffer_init.attachments' schema. Providers interpret member keys; Kernel
checks uniqueness, access and retention. The immutable state separately retains
which source states produced it; a live attachment is not historical provenance.
Staging captures source access under its retention grant; denied retention
leaves the original owner and Buffer unchanged. Saving still acquires
independent WRITE.

Aggregate factories declare whether they capture independently coherent
member states or require a joint snapshot authority. Unsupported joint capture
rejects; separately read files are not presumed to have coexisted at one instant.
Each selected source state supplies a precondition; the result's own Buffer
revision cannot replace that vector of input states.
[Buffer graphs](02-buffer.md) illustrate repository aggregation.

## Attach and refresh

```rust
buffer.attach_sources(expected, sources).await?;
buffer.detach_sources(expected, keys).await?;
buffer.refresh_from(expected, keys, RefreshPolicy::RejectModified).await?;
```

expected is BufferState, including the current revision; attachment changes
advance that revision without adding a History node. One-source attach/detach/
refresh/save capture current expected state at admission and select the single
default role. The explicit variants name keys and reject missing/ambiguous ones.
Attach stages the full relationship change, preserves state/History and never
marks content saved. Detach fences matching watch generations and retains
outstanding operation custody before releasing access; unrelated sources stay.

RefreshPolicy is RejectModified or DiscardLocal. The former requires unchanged
working state relative to its accepted import/publication base; the latter is
explicit authorization to replace local state. Refresh prepares an ordinary
candidate and therefore records an accepted History transition.
Provider-specific merge is a typed operation with its own conflict/result
declaration.

## Observation and capture

Buffer revision events, source events and attachment changes are distinct.
Source events identify the association generation; queued events from an old
source cannot apply to its replacement. [Observation](03-observation.md) owns
delivery and gap recovery. Watching neither refreshes nor cascades edits.
Reactive processing requires an explicit owner, bounds and cycle/re-entry
policy.

Streaming capture imports received data through ordinary Buffer acceptance.
Its API defines framing, batching, input/Buffer access, start boundary, status,
retention and known loss. Multiple streams require explicit ordering/alignment;
silence is not a synchronized boundary. A recovered receive returns its original
captured data under [request custody](01.3-requests.md).

```text
receive -> retain data -> accept import -> Buffer state + History
stop    -> fence new/late imports -> report final accepted state
```

Already accepted imports survive stop and input close. Buffer close stops its
capture; stopping one capture does not close shared endpoints or other captures.
A continuing capture after caller detach needs an explicit owner, such as an
authorized Session. Pause cannot promise to pause hardware or remote senders.

Bound aggregate fan-out/export retention. Rolling eviction declares what happens
to data, History and retained exports. Receive scratch memory cannot own
accepted state. Close drains/transfers outstanding capture/export work or
reports incomplete shutdown. [Live I/O examples](07.1-live-io.md) apply these
rules.
