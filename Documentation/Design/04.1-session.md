# 04.1 — Session state and participation

Types: [Resource access](01.2-resource-access.md), [watch](03-observation.md).
State is the agreed [Client-context](04-clients.md) schema. Runtime validates
its negotiated name/version and grants; a Rust parameter alone does neither.

A Session retains a virtual editing space under Client/module policy. Kernel
stores validated, versioned context data and enforces access/currentness; it
does not interpret that data as input, lay out a view or render output.

```rust
// Path: kernel/interface/src/session.rs; module: interface::session
pub struct Session<State> {
    pub id: ResourceId, // The live, server-held Session subject.
    pub snapshot: ResourceId, // This immutable context observation/seek target.
    pub state: State,   // Caller-owned value, not mutable Kernel storage.
}
pub struct SessionFollow<State> {
    pub current: Session<State>, // Baseline at the subscription boundary.
    pub watch: ResourceId,       // Subsequent Session<State> observations.
}
```

Snapshot identifies captured currentness, not an ordered counter. Returning to
equal payload after A -> B -> A cannot revive an old update precondition.
State copies never mutate server storage. Context retention does not retain
every referenced Resource's data.

| Call | Context behavior |
| --- | --- |
| create(initial) | New retained Session and initial snapshot |
| attach(session) | Create participation initially viewing live context |
| read(participation) | Return that participation's live or historical view |
| update(participation, expected, proposed) | Replace live context after schema/member/grant/currentness checks |
| follow(participation) | Atomically return SessionFollow with baseline and independent watch |
| seek(participation, snapshot) | Select retained context for this participation only |
| detach(participation) | End participation and its watches; keep separately owned snapshots |
| release_snapshot(snapshot) | End retained context access |
| close(session) | Settle the Session under its owner's close authority |

Seek grants no authority to overwrite newer live state. Seek/follow fences
prior streams; failure preserves the prior view. Gaps require fresh follow;
missing retained context never falls back to latest.

Each returned snapshot is caller-owned until release/declared expiry; copying
metadata creates no lease. Release invalidates the view, not copied State.
Participation/admitted work retains needed backing independently. Detach ends
its watches/navigation references while returned snapshots and Session
survive. Session close settles dependants, not shared Buffers. Caller-access
close drains or transfers its remaining snapshots and recovery ownership.

## Editing context schema

```rust
// Path: clients/common/src/session.rs; module: client::session
use alloc::vec::Vec;

pub struct EditingSessionState {
    pub active_buffer: Option<ResourceId>, // None: no selected Buffer.
    pub buffers: Vec<ResourceId>, // Known Buffer references, not ownership.
}
```

Reject duplicate buffers or active_buffer absent from buffers. Other schemas
may retain qualified cursors/selections; Kernel owns no viewport structure.

```rust
// Proposed Session helper; selected_buffer is in observed.state.buffers.
// participation comes from attach, observed from read/follow.
let mut proposed = observed.state;
proposed.active_buffer = Some(selected_buffer); // Context only.
let updated =
    sessions.update(participation, observed.snapshot, &proposed).await?;
// Keep the expected snapshot through admission; retain updated for next use.
```

These helpers encode the agreed State schema over common Resource requests.
Caller values stay unchanged on rejection. [Unknown outcomes](01.3-requests.md)
retain recovery access; transport retries cannot create a second Session
or participation.

Authorized namespace children can name Session context, snapshots and
participation. Names grant no access and create no extra owner.

## Module and Client-owned state

```text
sessions/work/modules/language-support/state // Session-scoped Kernel service.
global/modules/language-support/settings     // Shared Kernel service settings.
sessions/work/client-state/vim               // Client extension's own schema.
sessions/review/client-state/emacs           // Independent Client data.
// These are ordinary Resources under separately granted caller access.
// Adding a module does not extend a concrete Kernel Session struct.
```

Each state provider declares its schema, owner, update/currentness rules,
retention and explicit sharing. Kernel module instances execute in Kernel
Runtime; Client extensions follow their own lifecycle while accessing retained
Session data. Neither extends the Kernel Session struct with private fields.
Native view handles, code pointers and executor state remain private objects.

Session snapshots capture their declared context schema. They do not
automatically snapshot or retain every module-state child; aggregate capture
must retain the particular child observations it promises. Seeking a Session
view neither rewinds live module children nor replays input or external effects.

Retaining module state after code unload requires versioned data independent
of that code's storage/destructors. Reattach/restore needs compatible schema
or explicit migration. Otherwise the live value keeps its provider loaded;
see [module lifetime](06-modules.md) and
[native ownership](06.4-native-modules.md).
Closing a Session settles owned state and its scoped Kernel module instances.
Client participants observe closure and settle their local extensions through
their own contracts; Kernel cannot invoke their private loader. Each owner
retains unfinished cleanup. Session close does not unload shared global
providers or close shared Buffers merely because they were referenced.

The [future Client surface](07.3-client-resources.md) can name participation
focus below a Session. [Service workflows](07.2-service-workflows.md)
shows how Kernel modules follow context to provide language support.
