# 07.3 — Future Client Resource surface

Proposed extension direction, not a required Client feature or a finalized
protocol. A Client may export versioned Resource interfaces through its
connection. Kernel/server exposes authorized proxies in the
[resource tree](01.1-resource-tree.md); the Client remains their service owner.
Neither exports nor Session participation imply Kernel module registration.

## Discovery and access

Illustrative paths relative to an authorized root:

```text
clients/{id}/capabilities   // Supported export contracts/versions; no grants.
clients/{id}/framebuffer    // Coherent Client-produced frames + bounded watch.
clients/{id}/input          // Independent observation feed; no key consumption.
clients/{id}/log            // Access to that Client's diagnostic stream.
clients/{id}/notification   // Typed notification submission to the Client.
sessions/{sid}/buffer       // Stable selected-buffer context, not a moving ID.
sessions/{sid}/clients/{id}/focus // This participation's semantic focus state.
```

Actual children and operations come from advertised contracts. Capability
discovery is metadata; callers still need the exact contract and grant for each
[Resource request](01.2-resource-access.md).
Paths are aliases, not dispatch names or mandatory byte-file interfaces.
`self`, if offered, resolves within the caller's authorized participation.

```rust
// Proposed helpers; each export request checks its own contract and grant.
let framebuffer =
    tree.resolve_at(root, "clients/tui-1/framebuffer").await?;
let input = tree.resolve_at(root, "clients/tui-1/input").await?;
let log = tree.resolve_at(root, "clients/tui-1/log").await?;
let notification =
    tree.resolve_at(root, "clients/tui-1/notification").await?;

let frames = framebuffer_api.observe(framebuffer).await?;
// Client supplies a snapshot + watch for future frames.
let inputs = input_api.watch(input).await?; // Copies; visible loss gaps.
let logs = log_api.watch(log).await?; // Independent bounded reader.
let submitted =
    notifications.submit(notification, "Build finished").await?;
// Client decides display and routing.
// Accepted submission alone does not prove the user saw the notification.
```

An input observation grant gives no input-injection authority. Frame formats
and input schemas belong to their public export contracts; Kernel stores and
routes neutral references/payloads without interpreting them as UI behavior.
A debugger hosted at the server is still a consumer of these contracts.

Each export names its owner/lifetime. Disconnect closes or suspends access
according to the advertised contract; retained last values stay explicitly
stale. Reconnect resolves current instances without retargeting old IDs.
Capability removal, revocation and slow consumers follow
[observation](03-observation.md) loss/closure rules. A log export reuses its
owning [diagnostic stream](../debugging.md); it cannot generate itself.

## Peer focus

Focus belongs to the Client's participation in a Session. A schema can name
Buffer, Representation, qualified semantic anchors and an origin/currentness
value. It supplies no universal viewport or screen-coordinate type.

```rust
// Proposed wrappers; GUI/TUI explicitly share this Session.
// Inputs: tree/focus access and GUI-owned mapping/view APIs.
let peer_focus =
    tree.resolve_at(root, "sessions/work/clients/tui-1/focus").await?;
let mut follow = focus_api.follow_stream(peer_focus).await?;
// Optional helper yields baseline and watched updates; gaps are errors.
while let Some(focus) = follow.next().await? {
    let anchors = mapping.map_current(&focus, &view).await?;
    // Mapping validates source lifetime and semantic correspondence.
    view.follow(&anchors, &focus.origin)?; // Apply local follow policy.
    view.render().await?; // Local layout and rendering.
}
// Gap -> reacquire a baseline before continuing dependent updates.
// Unmappable anchors -> report unavailable mapping, never guess coordinates.
// Preserve origin; a received update must not bounce between followers.
```

Following focus synchronizes the selected content/anchors. The receiver's
dimensions and layout still determine its viewport. Exact visual mirroring
instead consumes an explicitly supported framebuffer export and presents it
through the receiving Client's own output path.

The export profile still needs registration/proxy routing, exact schemas,
snapshot/watch support, request completion and reconnect rules before
implementation. Verify independent Client/server implementations, unavailable
exports, read/write grant separation, input-reader isolation, focus mapping,
gaps, slow readers and disconnect.
