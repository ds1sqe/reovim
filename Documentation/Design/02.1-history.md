# 02.1 — History, Undo and Redo

Types: [BufferState](02-buffer.md), [Resource access](01.2-resource-access.md).
History, addressable nodes and retained inspection snapshots are Resources.
An edit adds a child; Undo follows the parent; Redo chooses a retained child.

```text
initial: "# Draft" -> renamed: "# Plan"
                  -> revised: "# Notes"
// Edit to Plan, Undo, then edit to Notes: both branches remain.
// Undo restores a node's state with a fresh Buffer revision.
// Returning to initial cannot make an old edit request current again.
```

```rust
// Path: kernel/interface/src/history.rs; module: interface::history
use alloc::vec::Vec;

pub struct HistoryNode {
    pub id: ResourceId,
    pub parent: Option<ResourceId>, // None at the retained tree's root.
    pub children: Vec<ResourceId>,  // Complete children at this observation.
    pub selected_child: Option<ResourceId>, // Default Redo; must be a child.
}
pub struct HistoryView {
    pub history: ResourceId,
    pub snapshot: ResourceId, // Retained coherent tree/metadata observation.
    pub state: BufferState,   // Buffer currentness captured with this tree.
    pub head: ResourceId, // Current node at that cut, not necessarily node.id.
    pub node: HistoryNode,
}
pub enum HistoryTransition {
    Edit { parent: ResourceId, child: ResourceId },
    Undo { child: ResourceId, parent: ResourceId },
    Redo { parent: ResourceId, child: ResourceId },
}
pub struct BufferChange {
    pub request: ResourceId, // Cause identity; may outlive retained work.
    pub before: BufferState,
    pub after: BufferState,
    pub history: ResourceId,
    pub transition: HistoryTransition,
}
```

## Inspection and traversal

- `inspect(history, None, ...)` creates a caller-owned snapshot of head,
  relations, preferences, retention metadata and Buffer observation.
  `Some(snapshot)` reads that cut without new ownership; foreign nodes reject.
- Metadata/Vec copies belong to the SDK and do not prune History on drop.
  Snapshots retain bounded backing, without requiring a whole-tree copy.
  Expired/released cuts are unavailable; oversized child listings return
  pressure instead of clipped success.
- Snapshot retention does not guarantee native Undo reconstruction or grant
  mutation. Undo/Redo checks live History and current BufferState.
  Missing edges return no-history; missing reconstruction is distinct.
- Admission selects the edge; commit rechecks edge, lifetime and expected state.
  Pending work cannot retarget. Traversal gives fresh Buffer currentness;
  rejection/cancellation before acceptance changes neither state nor tree.
- Edit creates/selects a child, preserving siblings after Undo. Explicit Redo
  selects the default child for later Redo. Node IDs imply no traversal order.

BufferChange is the result and accepted event payload. Metadata/backing
changes use invalidation, not a fabricated transition. Undo is local;
[publication](03.3-publication.md) owns external effects.

## Caller example

```rust
// Proposed History helper; buffer is an actual BufferDescriptor observation.
let change = history.undo(buffer.history, &buffer.state).await?;
// Client policy decides whether to follow change.after.
let cut = history.inspect(buffer.history, None, None).await?;
let redone = history.redo(buffer.history, &cut.state, None).await?;
history.release_snapshot(cut.snapshot).await?;
// None chooses the preferred child; Some(child) chooses that retained branch.
```

The helper's inspect(history, snapshot, node), undo(history, expected),
redo(history, expected, child) and release_snapshot(snapshot) use common
requests. Their results are HistoryView, BufferChange or completed release.
[Unknown outcomes](01.3-requests.md) retain recovery access; a lost reply
cannot justify a second traversal.

Namespace aliases such as history/head name these subjects; removing an alias
cannot prune History. Old views do not bypass stale checks.
