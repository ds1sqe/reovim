# Assembly, modules, Sessions and shared editing

Rust examples of the [public wiring](05.1-composition.md), using proposed
assembly and SDK methods. The SDK retains request/recovery identity across
`.await?` and errors under [request custody](01.3-requests.md). Declarations and
authorized names come from application composition.

## Assembly supplies access

```rust
// Proposed assembly API; inputs are configs and separately granted Hosts.
// Factories start each owner and wait for its required services to be Ready.
let kernel_owner = assembly.kernel(kernel_config, kernel_host).await?;
let tui_owner = assembly.tui(tui_config, tui_host).await?;
let gui_owner = assembly.gui(gui_config, gui_host).await?;

let kernel_control = kernel_owner.control()?;
let kernel_modules = &kernel_control.modules;
let tui_kernel =
    assembly.connect(&tui_owner, &kernel_owner, tui_grants).await?;
let gui_kernel =
    assembly.connect(&gui_owner, &kernel_owner, gui_grants).await?;
let tui_extensions = tui_owner.extensions()?;
let gui_extensions = gui_owner.extensions()?;
let tui_access = tui_owner.access()?; // Common access to Client contracts.
let gui_renderer = gui_owner.renderer()?;
let gui_output = gui_owner.output()?;
// Each owner retains/drives its lifecycle table/state and arranges wakeups.
// Only assembly imports selected implementations; consumers import APIs.
```

Kernel builds once. After it is running, a module author builds compatible
provider artifacts against the public SDK. The Host loader admits those
artifacts under the [native/service contract](06.1-native-abi.md).

```rust
// Proposed helper for module control; ModuleScope is defined in Modules.
let source_provider =
    kernel_modules.modprobe("sftp", ModuleScope::Global).await?;
let state_provider =
    kernel_modules.modprobe("bytes", ModuleScope::Global).await?;
let markdown_provider =
    kernel_modules.modprobe("markdown", ModuleScope::Global).await?;
// Dependencies resolve exact supported contracts and existing ready providers.
// The owner obtains metadata; Runtime retains the live implementations.
// markdown registers semantic/source/preview providers, never a renderer.
```

Resource access and the Buffer factory are separate selections. The SFTP adapter
has its own Host grants; another Resource implementation can support the same
public access contract. Missing permissions or incompatible declarations fail
before any ready Buffer/Representation is exposed.

## Session state and Client modules

The empty editing-session state below is
[EditingSessionState](04.1-session.md) with no buffers or active buffer.
ModuleScope is defined in [Kernel modules](05.2-modules.md); Client activation
has its own contract and receives authorized Session/service access.

```rust
// Proposed SDK; initial values use the declared EditingSessionState schema.
let work = tui_kernel
    .sessions
    .create(&EditingSessionState {
        active_buffer: None,
        buffers: Vec::new(),
    })
    .await?;
let review = gui_kernel
    .sessions
    .create(&EditingSessionState {
        active_buffer: None,
        buffers: Vec::new(),
    })
    .await?;
let work_participation = tui_kernel.sessions.attach(work.id).await?;
let review_participation = gui_kernel.sessions.attach(review.id).await?;

// Composition exposes these Sessions under sessions/work and sessions/review.
let kernel_work = kernel_control.open(b"/sessions/work").await?;
let language_service = kernel_modules
    .modprobe("language-support", ModuleScope::Session(kernel_work.id()))
    .await?;
// This Kernel service follows work's Buffer context under its own policy.

let work_scope = tui_extensions.resolve_session("sessions/work").await?;
let review_scope =
    gui_extensions.resolve_session("sessions/review").await?;
let vim_instance = tui_extensions.activate("vim", work_scope).await?;
let emacs_instance = gui_extensions.activate("emacs", review_scope).await?;
let vim = vim_api::at(&tui_access, vim_instance.resource);
// at constructs a local codec/helper; it acquires no new access lifetime.
// Client activation checks required public services; it is not Kernel modprobe.
// References cross connections only through authorized resolution/proxies.
// Vim state belongs to work; Emacs state belongs to review.
// Explicit global settings are granted imports, not shared private memory.
```

Kernel modules receive [ModuleContext](05.2-modules.md). Client modules receive
granted access through their own activation contract. Their logical dependencies
can cross owners while live instances and retained state remain independent.
The [navigation/help example](07.3-navigation.md) details those imports.

## One Buffer, two user views

```rust
// Inside the interested Client workflow modules.
// Composition supplies checked source_api, preview_api and files handles
// from Markdown and file API packages under each Client's caller grants.
let source = tui_kernel.open(b"/files/notes").await?;
source.set_access(Access::READ).await?;
let draft = tui_kernel.buffers.create(&source).await?;
// The configured factory creates independent working state and History.
// Authorized composition exposes this Buffer under "buffers/draft".

let draft_reference = gui_kernel.open(b"/buffers/draft").await?;
let joined = gui_kernel.buffers.find(draft_reference.id()).await?;
let source_representation = source_api.attach(draft.state.buffer).await?;
let preview_representation =
    preview_api.attach(joined.state.buffer).await?;
// Update work/review's active Buffer through each Session's context API.
// The two connections use their own Resource references to the same Buffer.
```

The TUI constructs its source viewport; the GUI constructs its preview view.
Their Client Runtimes handle keys, text/IME, pointers, layout, rendering and
user-facing output. Kernel interprets no viewport, raw input or renderer.
Representation access supplies semantic observations and edit correspondence.

```rust
// Proposed SDK; input comes from the TUI Client's input adapter.
let observed = source_api.observe(source_representation).await?;
let heading_edit = vim.resolve_edit(&input, &observed.snapshot).await?;
let changed = source_api.edit(&heading_edit).await?;

// Runtime invokes the declared state preparation binding.
// Core revalidates and installs state + History atomically.
// Client waits for acceptance and matching observation before responding.
// GUI renders new preview data; its selection/follow policy stays independent.

let preview = preview_api.observe(preview_representation).await?;
let preview_frame = gui_renderer.render(&preview.snapshot)?;
gui_output.present(preview_frame).await?; // Client output; no Kernel draw call.

let restored =
    tui_kernel.history.undo(draft.history, &changed.after).await?;
let saved = files.save(&restored.after).await?;
// Undo is local. Save explicitly publishes through the SFTP Resource adapter.
// Later edits stay unsaved; conflicts or uncertain effects remain visible.
```

Creation failure exposes no partial Buffer. An unnamed Buffer uses
factory-defined initial state; first Save As publishes before conditionally
associating its backing. Failed association leaves the real file effect visible.

A failed preview cannot roll back an accepted edit. Stale semantic values
require fresh observation or explicit correspondence. Both behavior modules
use the same Buffer/History APIs; neither can install private Core plans.

## Unload and retained state

```rust
// Proposed SDK; each execution owner tears down its own modules.
tui_extensions.deactivate(vim_instance).await?;
// Client owner removes keymaps, fences pending input and drains module work.
// Accepted Buffer edits remain. Declared independent Session data may remain.
// Restore later only with compatible schema or explicit migration.

let unload = kernel_modules.unload(state_provider.resource).await;
// Busy while draft/History/leases or required providers need this code.
// Busy leaves the active instance and its contributions available.
```

For complete teardown, deactivate emacs_instance through gui_extensions.
Settle language_service through Kernel modprobe's unload API. Detach Session
participants; release source/preview observations and watches;
detach Representations and unload semantic dependants when no longer needed.
Close the Buffer only under its current modified-state policy, then release
remaining leases and explicitly close remaining owned Resource endpoints
before unloading the state/Resource providers. Global
providers still used elsewhere remain active. Kernel keeps serving unrelated
work throughout; each instance releases code only after required uses finish.

All steps use public APIs and separately owned Client sessions. Reconnect
recovers the original request's result; it cannot repeat an uncertain edit.
These sketches describe the target journey, not a running implementation.
